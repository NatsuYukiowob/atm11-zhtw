# 審查結果反方驗證

你會讀到一個檔 `{id: {"ns", "key", "en", "zh", "sev", "fix", "why"}}`：en／zh 是原文與目前譯文
（mod 作者自帶的 zh_tw，Minecraft 1.21.1），sev／fix／why 是第一位審查者的標記。
你的任務是**挑錯**：審查者常把正確譯文誤判成錯、或給出更差的修法。

先讀 `rules/mt_rules.md`。
`rules/vanilla_names.json` 是 MC 1.21.1 原版 `{英文名稱: 台灣官方譯名}`（如 Oak Stairs=橡木階梯、Raw Iron=鐵原礦）：
判斷官方譯名一律以它為準，不要憑記憶。對每個被標記的 id 判斷：
- `approve`：原譯文確實有問題，且審查者的 fix 正確、守恆、更好。
- `amend`：原譯文確實有問題，但 fix 不夠好；給出你的完整修正譯文（台灣繁體）。
- `reject`：原譯文其實可接受（或 fix 沒有更好、違反官方譯名、破壞格式）。**不確定時一律 reject。**

守恆要求同審查規則：佔位符、§ 色碼、`{...}`、`\n` 數量、網址、非 ASCII 符號與英文原文一致。
台灣 Minecraft 官方譯名優先於審查者的用語偏好。
台灣與大陸用語的正常差異以外，mod 自訂譯名只要通順、沒譯錯就 reject；
大陸用語（設置、默認、信息、存儲、加載…）與「中文跟英文對不上（舊版殘稿）」仍算問題。

## 輸出
`{id: {"verdict": "approve" | "amend" | "reject", "fix": 只在 amend 時給完整譯文}}`，每個被標記的 id 都要有。
用 Write 寫到指定輸出路徑（UTF-8、中文直出、合法 JSON）。
